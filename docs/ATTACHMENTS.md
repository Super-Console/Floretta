# 附件

状态：生效
建立：2026-11-10

图片、视频、音频，以及塞进导图的其他文件，都按下面办。格式矩阵见 `docs/FORMATS.md`。流式读写、内存天花板和 ZIP 布局见 `docs/STREAMING.md`。数字天花板与 `docs/PERF-BUDGET.md` 同一组。

## 1. 软上限 10GB

以前的「单文件 100MB」「视频 50MB」作废。不再用这两个数拒绝、裁切或降级。

软上限是 **10GB**（`StreamingBudget.softCapBytes`）。10GB 以内按原样放入。超过 10GB 不另设硬拒绝：确认文案写明已超过软上限，用户确认后仍按同一条流写入。内存不按这个数分配。

硬规矩是另一条：写入峰值 RAM 小于 32MB，且不随文件变大；任何路径都不得把整份附件读进内存。打开带 10GB 附件的文档时，进程 RAM 增量小于 50MB。见 `docs/STREAMING.md`。

坏包仍然拒绝：条目畸形、声明的大小和局部头对不上、加密、data descriptor、附件用了压缩方法而不是 stored。那是防坏 ZIP，不是给正常附件卡体积。

`ZipContainer` 内存 API 上的 16MB / 32MB 只约束「整包已经在 `Data` 里」的小包读写，不是产品上限。

## 2. 大附件插入前确认，且不卡住界面

插入前先确认，再写入。确认只读文件大小（`stat`），不哈希、不转码、不等压缩，界面不卡住。

确认上必须写清：

- 这个文件有多大
- 字节会原样放进当前项目
- 放进去之后整份文档大约有多大（去重前的上界）

超过 10GB 软上限时，确认里再写明这一点。

用户取消则不插入、不写盘。点确认之后才流式哈希并写入。视频和音频走同一条确认，不因为类型而压缩。

## 3. 原样字节

禁止有损压缩、降采样、重新编码。ZIP 方法 0，压缩前后大小相同。导出这份附件必须和插入时的字节一致。

sha256 只用来去重和校验完整性（容器路径 `assets/<sha256>.<ext>`）。哈希相同就复用已有字节，不同就另存。不用哈希当转码的理由。打开文档时不算附件哈希，避免为了校验把正文读进来。

## 4. 体积要看得见

节点上显示该附件的大小（每个附件一行：文件名和字节数）。文档信息（检查器「导图」）里显示附件合计，合计按包内 `assets/` 的存储字节、同一 sha256 只算一次。

## 5. 视频和音频

与上面相同：不压缩、不改封装、不改码率、不抽帧。只做体积确认。导出字节与源文件一致。

## 6. 打开、缩略图、备份

打开文档只读 ZIP 中央目录和 `document.json` / `metadata.json`，不读附件正文。

缩略图懒加载。进入视口才把附件按块写到 spill，由 `ImageIOThumbnailDecoder`（ImageIO，最长边 256）做成小图，放进磁盘缓存（≤ 200MB，LRU），并画在节点上。画的时候按宽高比放进槽里，不裁切。解码不占主线程。滚出视口就卸掉内存里的图，磁盘缓存留着。spill 用完即删。正文不留在 RAM。

图片可以从文件选择、拖放、剪贴板粘贴进来，三条都先确认再按原字节写入。导出 PDF/PNG 时按页面需要的分辨率从 spill 再解码一次，不拿 256 的缩略图放大。

`Application Support/Floretta/Attachments` 排除 iCloud / 设备备份，避免备份被缩略图和 spill 撑大。用户自己的 `.floretta` 不在这个排除范围内。

## 7. 任意文件

PSD、PDF、DMG，以及文件选择器里的其他类型，走同一条插入：先 `stat` 出大小，确认文案写明这个文件有多大和放入后文档大约有多大，确认之后才按 1.2 的流式写入和 sha256 去重落盘。不压缩，不转码。

类型用 UTType 认。系统有类型图标就画那个图标；没有（例如未登记的扩展名，或 PSD 在这台机器上没有图标）就画通用文件图标。节点上每个非图片附件一行：图标、文件名、大小。图片仍走 1.3 的缩略图，不改成这一行。

点这一行用 QuickLook 预览：macOS 是 `QLPreviewPanel`，iOS 是 `QLPreviewController`。预览读的是流式 spill 出去的副本，不是整份读进内存。预览过程中这份文件没了，关掉预览并提示「这个文件已经不在，预览已关闭。」，不崩溃。
