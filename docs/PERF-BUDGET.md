# 性能预算（PERF-BUDGET）

这些是**硬门槛**，不是目标。每个 PR 必须附「性能影响三行」（内存 / 帧率 / 包体），缺一行打回。

## 十条门槛

| # | 项目 | 门槛 | 验收方法 |
|---|---|---|---|
| 1 | 冷启动（macOS / iPad） | < 800ms 到首帧，< 1s 可交互 | Instruments / 启动时间戳 |
| 2 | 打开 1000 节点文档 | < 1.5s | 单测 + 实测 |
| 3 | 拖动与缩放 | ≥ 55fps（120Hz 屏 ≥ 100fps） | 帧率采样 |
| 4 | 1000 节点 + 20 张图 常驻内存 | < 250MB | 进程 RSS |
| 5 | 打开含 10GB 附件的文档，内存增量 | < 50MB（流式，不整体载入） | 打开前后 RSS 差 |
| 6 | 附件写入峰值内存 | < 32MB，且与文件大小无关 | 写入大文件时采样 |
| 7 | 缩略图缓存 | 上限 200MB，LRU 淘汰 | 缓存单测 |
| 8 | 空闲 CPU | < 1%，无常驻后台线程/定时器 | Activity Monitor / 采样 |
| 9 | 包体 | iOS < 15MB，macOS < 25MB | **已由 CI 强制**：`Packaged app size` job；超限失败，且禁止 Node/Python 运行时及相关依赖清单 |
| 10 | 网络 | 默认零请求，且有可审计开关 | 抓包 + 代码审查 |

## 约束

- 任何"为了功能牺牲门槛"的改动，必须在 PR 里显式说明并给出实测数字，由审查方决定
- 附件一律原字节、零转码；压缩换性能是不允许的
- 播放/预览大媒体文件必须流式，不得整体读入内存
- 缩略图、解码、索引一律异步，主线程只做 UI
