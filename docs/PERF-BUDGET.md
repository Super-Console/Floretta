# 性能预算

状态：生效
建立：2026-11-10

这些数字是上限，不是目标愿望。新功能提案先按本预算设计。不许写「以后再优化」。超了就改设计，不进「以后」。

审查对照 `docs/REVIEW-WORKFLOW.md`。PR 描述里要有三行「性能影响」：内存、帧率、包体各一行。缺一行即阻断。

## 启动

- macOS 与 iPad 冷启动 < 800ms。
- 冷启动后可交互 < 1s。

## 打开文档

- 打开 1000 个节点的文档 < 1.5s。不计附件解码。
- 打开含 10GB 附件的文档，进程内存增量 < 50MB。这是流式读取的证明：附件在磁盘上，不整包进内存。

## 画布

- 平移、缩放 ≥ 55fps。
- 120Hz 设备上 ≥ 100fps。

## 内存

- 1000 个节点加 20 张图片 < 250MB。
- 写入附件时的内存峰值 < 32MB，并且不随文件变大。1MB 和 10GB 都是这个峰值。
- 缩略图磁盘缓存上限 200MB，用 LRU 淘汰。这是磁盘缓存，不是常驻内存。

## 空闲与进程

- 空闲 CPU < 1%。
- 不驻留辅助进程。没有后台常驻的 helper。

## 包体

- iOS 安装包 < 15MB。
- macOS 安装包 < 25MB。
- 记下的现状大约是 iOS ~6.1MB、macOS ~7.7MB。这是记录，不是这次重测。上限仍是上面两行。

## 网络

- 默认零网络请求。
- 要有审计能证明这一点：冷启动后静置，记录本进程的出站连接，结果必须是零。审计结果写进审查证据。
- 某功能若要联网，先改本预算并写明何时发起。不能先接上再补审计。

## 提案

每一条新功能提案都先对上表。写得下，才做。写不下，就改范围。不留「上线后再优化」。
