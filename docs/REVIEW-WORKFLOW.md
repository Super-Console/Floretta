# 审查工作流（Censor）

状态：生效
建立：2026-11-10

## 为什么要有它

交付前靠"编译通过 + 单元测试绿"是不够的。已经出现过的问题：

- 面板没有退出路径，用户进得去出不来
- 同一个功能有三个入口，另一个常用功能零入口
- 顶栏全变成纯文字按钮，图标全丢
- 24 个模板里 18 个是同一棵树换颜色
- 侧栏有两个一模一样的开关、一条粘错位置的阴影
- 深色模式下大片纯白卡片

这些都不是"代码错"，是**产品完整性没被检查**。所以要有一个只做审查、不做实现的角色。

## 角色定义

**Censor 是审查者，不是实现者。** 它不改业务代码，只产出审查报告。
实现交给执行者（Floretta bot / 各 agent），Censor 判定。分离的原因很简单：
写代码的人对自己写的东西有确认偏误，看得见"我实现了"，看不见"用户点不到"。

## 触发时机

| 时机 | 是否必须 |
|---|---|
| 任何 TestFlight 构建上传前 | **必须** |
| 任何 PR 合并进 main 前（改动涉及 UI / 交互） | **必须** |
| 纯文档、纯测试、纯格式解析改动 | 可跳过 |
| 网站部署前 | **必须**（可达性 + 链接 + 移动端） |

## 审查清单（按此顺序，逐条给结论）

### A. 可达性（最高优先级）

1. 每个功能是否有**至少一个可见入口**？入口在哪、路径是什么？
2. 每个全屏 / 模态 / 文档页面是否有**可见退出路径**？三端分别验。
3. 是否存在**同一功能的多个入口**？（快捷键不算重复）
4. 是否存在**只有快捷键、没有可见入口**的功能？

### B. 表达规范

5. 操作按钮是否用图标（SF Symbols / SVG），而不是纯文字？
6. 菜单项是否为「图标 + 文字 + 快捷键」？有没有一堆只有文字的菜单？
7. 同一类控件是否全局只出现一次（侧栏开关、设置、新建）？

### C. 内容真实性

8. 是否存在占位假数据（灰块缩略图、克隆模板、Lorem 文案）？
9. 列表/模板/示例之间**是否有真实差异**？给出差异说明，说不出来就是不合格。
10. 文案是否有机器翻译味、错别字、重复词？

### D. 视觉一致性

11. 浅色与深色是否都检查过？有没有写死的 white/black 导致深色下刺眼？
12. 材质是否一致（液态玻璃 / 毛玻璃 / 哑光）？有没有混用？
13. 阴影、圆角、间距是否来自同一套 token？有没有孤立的魔法数字？

### E. 性能与体积

14. 大量数据（1000 节点）下拖动、缩放是否流畅？
15. 缩放极限下文字是否可读（有没有糊字、重叠）？
16. 体积增量是多少？有没有引入运行时（Node / Python / Electron）？

### F. 三端一致性

17. macOS 与 iPad 是否共用同一套设计逻辑？（同一组件、同一色板、同一间距）
18. iPhone 是否只是"空间更小"，而不是"另一套产品"？
19. 平台差异是否被明确写下来（哪些功能是桌面独占）？

## 报告格式

```
审查对象：<commit / build 号>
审查时间：
结论：通过 / 有条件通过 / 阻断

阻断项（必须修，不修不许发）：
1. [类别] 问题描述 —— 证据（截图路径 / 文件:行号）—— 修复要求

建议项（可发，但记入 backlog）：
...

已确认合格项：
- ...
```

规则：

- **每条结论必须带证据**：文件行号、截图路径、实测数字。不接受"看起来还行"。
- **阻断项不许含糊**："退出路径缺失"合格；"交互可以更好"不合格。
- 报告写入 `docs/reviews/REVIEW-<日期>-<对象>.md`，不覆盖历史。
- 审查者**不得修改**被审代码，避免自己给自己放行。

## 与执行者的关系

- 执行者提交 → Censor 审查 → 阻断项回给执行者 → 修完复审 → 通过才上传/合并
- Censor 与执行者**并行工作**，不互相等待：执行者做下一项时，Censor 审上一项
- Censor 的结论**不替代**用户本人的验收

## 已知的失效模式（要防的）

| 失效模式 | 怎么防 |
|---|---|
| 审查只跑一遍就放行，改动后没复审 | 复审绑定 commit hash，hash 变了必须重审 |
| 审查者被实现细节带跑，忘了用户视角 | 清单第一条永远是"用户怎么点到它" |
| 报告写满"建议"，真正阻断的问题被稀释 | 阻断项与建议项分区，阻断项不超过 5 条且必须具体 |
| 审查变成形式主义盖章 | 每次审查必须至少提出 1 条真实发现，否则视为无效审查 |
