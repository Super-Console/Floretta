# TASKBOOK-006 — AI 适配与格式互通（T0）

状态：待实现
优先级：**T0**，与 UI 打磨并行，不得无限期后置
适用：macOS / iPadOS / iOS 三端共享层

---

## 0. 一句话

**让 AI 能读写用户的导图，让用户的文件能在 XMind / 幕布 / 其他工具之间来回搬而不损失。**

这两件事是同一个目标的两面：文件不属于 App，属于用户。产品越轻、越本地，越要在「能被别的工具接住」上做得比大厂更狠。

---

## 1. AI 适配（三层，从便宜到贵）

### 1.1 第一层：文件本身就是 AI 友好的

- `.floretta` 容器里的 `document.json` 必须是**稳定、带 schema 版本、字段名自解释**的纯 JSON（当前已是，保持）。
- 额外保证：任意节点都能用 `id` 稳定寻址；中文不做 Unicode 转义（`ensure_ascii=False`）。
- 理由：AI 不需要任何 SDK，直接读文件就能理解结构。这一层**零成本，必须一直守住**。

### 1.2 第二层：本地 MCP server（重点）

随 App 附带一个**极小的 MCP server**，stdio 传输，不常驻、不联网、由客户端按需拉起。

工具集（第一版只做这些，不要膨胀）：

| 工具 | 作用 | 权限 |
|---|---|---|
| `list_documents` | 列出最近文档（路径、标题、修改时间） | 只读 |
| `read_document` | 读整棵树（可 `depth` 限制） | 只读 |
| `search_nodes` | 按文字搜索节点，返回 id + 路径 | 只读 |
| `export_markdown` | 导出为 Markdown 文本 | 只读 |
| `insert_node` | 在指定父节点下插入子节点 | **需用户确认** |
| `update_node` | 改文字 / 备注 | **需用户确认** |
| `move_node` | 换父节点 / 调顺序 | **需用户确认** |
| `import_markdown` | 从 Markdown 大纲新建文档 | **需用户确认** |

硬性要求：

- **默认只读**。任何写操作必须经过一次系统授权（macOS 用 App 内的确认面板，iOS 不支持写操作，只读）。
- 一次写操作 = 一次**可撤销事务**（进 Undo 栈），用户 `⌘Z` 能整体退回。
- MCP server 只暴露用户显式授权的目录，不扫全盘。
- 不引入大依赖：用官方 MCP SDK 的最小子集，二进制体积增量目标 **< 3 MB**。
- 安装方式：App 内「设置 → AI 接入」一键写入 Claude Desktop / Cursor / Codex 的配置文件（只追加自己那一条，不动别人的）。

验收：

1. 用 Claude Desktop 通过 MCP 连上，`list_documents` 能列出本地文档。
2. `read_document` 读出一份 50 节点的图，层级正确。
3. `insert_node` 加 3 个节点 → App 里立即可见 → 一次 `⌘Z` 全部撤销。
4. 断网状态下全部功能可用。

### 1.3 第三层：CUI（电脑操作）

不做额外开发，只保证「能被 CUI 驱动」：

- 所有可交互控件有正确的 accessibility label（按钮不能只有图标没名字）。
- 画布节点在无障碍树里可枚举、可聚焦（已有 `.focusable()` 基础，注意别为了去焦点环把可访问性一起删掉）。
- 关键操作用标准菜单项暴露（`File → Open`、`Edit → Undo`），让 CUI 与 AppleScript 都能走菜单。

## 2. 格式互通（T0）

### 2.1 分级承诺（对外文案必须照这个说，不许吹）

| 内容 | 承诺 |
|---|---|
| 层级、文字、备注、标签、超链接、折叠状态 | **高保真双向** |
| 主题配色、字体、线型 | 尽力映射，不保证一致 |
| 关系线、概要、边界、贴纸、附件、录音、多画布 | **原样保留（pass-through）**，不改就写回 |
| XMind 私有扩展字段 | 能读就读，读不懂原样留着 |

对外一句话：**「打开你的文件，改你想改的，导出后原软件还能正常打开，核心内容一个字不少。」**

### 2.2 pass-through 容器设计

`.floretta` 容器新增（只在导入外部文件时出现）：

```
document.json          # 我们自己的模型（权威）
foreign/
  xmind/
    manifest.json      # 来源 App、版本、原始文件名、导入时间
    content.json       # 原始 content.json 原样字节保存
    resources/         # 原始附件原样保存
```

导出规则：

1. 用户**没动过**某个我们不支持的属性 → 从 `foreign/xmind/content.json` 原样回写。
2. 用户动过相关节点 → 用我们的模型重建该子树，其余部分仍原样回写。
3. 导出结束时给一份**导出报告**（用户可见）：写清了什么、保留了哪些、哪些可能丢失。

### 2.3 支持矩阵（2026-11 调研，按真实存量排序）

| 格式 | 工具 | 导入 | 导出 | 结构 | 说明 |
|---|---|---|---|---|---|
| `.xmind`（2020+） | XMind | ✅ T0 | ✅ T0 | ZIP + `content.json` | 主战场，**只做新版**；XMind 8 的 `content.xml` 只读 |
| `.opml` | 幕布/Workflowy/OmniOutliner/Dynalist | ✅ | ✅ | XML 大纲 | 一份覆盖一大片，性价比最高 |
| `.md` | 通用 / AI | ✅ | ✅ | 缩进大纲 | AI 的公共语言 |
| `.mm` | FreeMind / Freeplane | ✅ | ✅ | XML | 已实现 |
| `.mmap` | MindManager | ✅ T1 | 暂不 | **ZIP + XML** | 企业用户存量 |
| `.itmz` | iThoughts（iPad 老牌） | ✅ T1 | 暂不 | **ZIP + XML** | 官方承认导入是有损的 |
| `.smmx` | SimpleMind | ✅ T1 | 暂不 | ZIP + XML | 同上 |
| `.emmx` | 亿图 / MindMaster | 评估 | 暂不 | 私有 | 国产存量，先只读尝试验证 |
| `.mindnode` | MindNode | ❌ | ❌ | 未公开 | 官方只对外给 OPML / TextBundle，靠 OPML 承接 |
| `.mubu` | 幕布 | ❌ | ❌ | 无公开规范 | 用 OPML 承接 |
| `.canvas` | Obsidian | ✅ T2 | ✅ T2 | JSON | AI/知识库用户，结构接近，成本低 |

**关键做法：ZIP + XML 通用桥**

`.mmap` / `.itmz` / `.smmx` 三者都是「ZIP 内含 XML」的同族结构。写**一个**通用读取器：
解压 → 找主 XML → 按根节点特征判定是哪一家 → 走各自的字段映射表 → 落进我们的模型。
一份解析骨架 + 三张薄映射表，比写三个解析器便宜得多。

**不做的**：`.mubu`、`.mindnode` 私有格式（无公开规范，靠 OPML 承接）；
`.emmx` 第一版只做「能不能读」的可行性验证，不承诺。

### 2.4 fixture 往返测试（必须先建）

`Tests/Fixtures/Formats/` 下至少 10 个真实样本：

1. 单层 3 节点
2. 五层深链
3. 100 节点宽树
4. 带备注 + 标签 + 超链接
5. 带主题配色与自定义字体
6. 带关系线
7. 带概要（summary）
8. 带边界（boundary）
9. 带图片附件
10. 多画布（多 sheet）

每个样本跑：**导入 → 导出 → 再导入**，断言三遍的节点数、文字、层级、备注完全一致；能识别的样式属性一致。

**没有这套 fixture，兼容性不许发版。**

## 3. 介绍页要写的话（交给 Web）

- 一张对照表：支持哪些格式、哪些双向、哪些只读。
- 一段「你的文件不属于这个 App」的说明：本地优先、不登录、导出不锁死。
- 一段「AI 可以直接读你的导图」：MCP 只读 + 写操作需你确认 + 可一次撤销。

不要写成营销腔，就写事实和边界。

## 4. 不做

- 不做云同步、不做账号体系（与本地优先冲突）
- 不做 `.mubu` / `.mmap` 第一版
- 不为兼容性引入 GPL 代码（SimpleMindMap 是 MIT，只借字段映射思路，不搬 JS）
- 不允许 MCP 在无用户确认的情况下写入
